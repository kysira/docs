    Releases¶

    What shipped in each version of the Argus proxy, ext-proc, inference sidecar, and dashboard. Dates are when the tag was cut.

    v0.7.9 — November 19, 2026¶

    • Fix: the inference chart's optional NetworkPolicy now matches the ext-proc and nginx-auth-adapter charts. Its default selectors looked for pods labelled app.kubernetes.io/name: ext-proc and nginx-auth-adapter, but those charts label their pods app.kubernetes.io/name: kysira-ext-proc and kysira-nginx-auth-adapter. With networkPolicy.enabled set (it is off by default), ext-proc and the nginx adapter were blocked from reaching inference, and because both fail open, requests passed through unscored. The defaults are now the chart names, set by the new values networkPolicy.extProcName and networkPolicy.nginxAdapterName.
    • If you enabled the policy and worked around this with same-namespace entries under additionalIngressSelectors, you can remove them. Entries with a namespaceSelector (callers in another namespace) are still needed.
    • The standalone kysira-proxy chart is not in the defaults. If you run it against a separately installed inference, add app.kubernetes.io/name: kysira-proxy under additionalIngressSelectors.
    • The policy limits who can reach the inference port. Metrics and health share that port with scoring, so they are restricted too, apart from Prometheus in the monitoring namespace.
    • Docs: the /health and /score/all examples in the API reference show the current fields, and the budget header is documented as X-Kysira-Budget-Ms throughout.
    • Release images include the operating-system package updates available on the day they are built, plus other security and package updates.

    v0.7.8 — November 6, 2026¶

    • The decision log now says why a request was scored regex-only. A degraded: true decision also carries degraded_reason: queue_full (inference's wait queue was full) or budget (the call could not finish inside the timeout, or no model slot freed up in time). Use it to tell an undersized inference service from a timeout that is set too low — see Observability and Sizing inference. Deploy ext-proc and inference in either order; an older inference simply sends no reason.

    v0.7.7 — November 4, 2026¶

    • Inference checks the Argus trim settings against the checkpoint. It reads the trim settings a checkpoint was trained with from the checkpoint itself and logs an error at startup if your configured settings don't match. /health shows the trained settings.
    • New KYSIRA_ARGUS_TRIM_ANCHORED option, off by default. It confines the trim to the header block, so body text after the first blank line is never trimmed. Enable it only together with KYSIRA_ARGUS_TRIM_SKIP_ENCODED, and leave both off unless Kysira support advises otherwise. In the chart (Deployment mode only) they are config.argus.trimAnchored and config.argus.trimSkipEncoded.
    • Security and package updates.

    v0.7.6 — October 12, 2026¶

    • Build-pipeline maintenance only. No change to ext-proc or inference behaviour — nothing to do if you are already on v0.7.5.

    v0.7.5 — October 12, 2026¶

    • Inference images are now multi-architecture (amd64 and arm64), so the same tag runs on Arm nodes.
    • Licensing no longer reads the cluster. The agent no longer calls the Kubernetes API at boot. The chart drops the related ServiceAccount and ClusterRole and the licensing.clusterFingerprint value; remove that value from your overrides.
    • Blocked requests no longer explain themselves. The 403 body is now {"error":"forbidden","detail":"request blocked by Kysira WAF"} and ext-proc no longer sets x-kysira-score on it. The score and reason stay in the decision log and metrics. If anything parses the old body or header, update it — see the API reference.
    • Typos no longer turn protection off. An unrecognised LICENSE_ENFORCEMENT or KYSIRA_MODE value now stops the service at startup instead of falling back to a permissive default. An ext-proc deployment that set the old MODE=active without KYSIRA_MODE also refuses to start, instead of silently running in shadow. Check your settings before upgrading.
    • Bounded scoring cost on hostile input. Detector cost now scales linearly with request size. Request text is capped at KYSIRA_MAX_REQUEST_TEXT (131072 characters by default) for the detectors, keeping the start and end rather than rejecting the request.
    • Inference chart hardening. New containerSecurityContext and a RuntimeDefault seccomp profile, plus an optional NetworkPolicy (networkPolicy.enabled, off by default) that limits who can reach the scoring endpoints. Before v0.7.9 its default selectors did not match the ext-proc and nginx-auth-adapter charts, so enabling it blocked both from inference and requests passed through unscored. Add app.kubernetes.io/name: kysira-ext-proc and app.kubernetes.io/name: kysira-nginx-auth-adapter under networkPolicy.additionalIngressSelectors before enabling it, or use the v0.7.9 chart — see the v0.7.9 entry.
    • Model weights in release images are pinned and verified.
    • Chart: config.argus.trimMinRun and config.argus.trimKeep expose the Argus header-trim settings (Deployment mode only). Defaults are unchanged.
    • Security and package updates.

    v0.7.4 — October 1, 2026¶

    • Fix: key-grant requests used a default CA file path that nothing ships, so they failed even when licensing was reachable (logged as key-grant stage failed). With AGENTS_SERVER_CA_PATH unset they now use the system trust store.
    • Detection: SQL injection obfuscated with comments or slashes is now caught by a model-independent signature rule. Plain select … from … text in prose is unaffected.
    • Docs: new section on the Global External Application Load Balancer — see the GCP deployment guide.

    v0.7.3 — September 24, 2026¶

    • Quieter admission-probe logging in the inference sidecar.
    • Docs: new guidance on sizing inference for scale-out — see Sizing inference.

    v0.7.2 — September 24, 2026¶

    • Fix: active mode could still fall back to regex-only scoring when traffic repeats the same request. If you are on v0.7.0 or v0.7.1 in active mode, upgrade.

    v0.7.1 — September 24, 2026¶

    • Fix: active mode fell back to regex-only scoring on most requests under v0.7.0 defaults. Inline INFERENCE_TIMEOUT_MS now defaults to 300 ms (keep it below your traffic extension timeout — see Timeout ordering).
    • More accurate inference cost estimates, so a single slow request no longer locks the model out.

    v0.7.0 — September 24, 2026¶

    • Bounded inference latency. The inference sidecar limits concurrent scoring and falls back to regex and signature detection when it can't finish in time, instead of queueing or erroring. Set KYSIRA_ADMISSION=off to restore the previous behaviour.
    • Faster Argus scoring on requests with long tokens in Authorization and Cookie headers.
    • Circuit-breaker improvements.
    • Request headers on the decision log, with sensitive values redacted. Disable with KYSIRA_LOG_HEADERS=false.

    v0.6.4 — September 18, 2026¶

    • Argus v5 detection model.
    • Security and package updates.
    • Images are now also published to Amazon ECR. Release images no longer carry a latest tag — pin a version.
    • Fixed the license-signing public key in the inference image.

    v0.6.2 — August 28, 2026¶

    • Circuit-breaker activity is now visible in the logs. ext-proc logs when the breaker opens and closes and when it sheds a request, so a burst of fail-open traffic can be traced to the breaker instead of guessed at. Adds the kysira_extproc_breaker_open, kysira_extproc_breaker_opens_total and kysira_extproc_breaker_short_circuit_total metrics.
    • Troubleshooting guide covers breaker behaviour — what an open breaker looks like from the caller's side, and what to check when it stays open.

    v0.6.1 — August 28, 2026¶

    • Release and build-pipeline maintenance only. No change to ext-proc or inference behaviour — nothing to do if you are already on 0.6.0.

    v0.6.0 — August 28, 2026¶

    • Shadow-mode scoring moved off the request path. In shadow mode ext-proc now answers immediately and scores in the background, so scoring latency never reaches the caller. Tunable with shadowAsync, shadowWorkers and shadowQueue; set shadowAsync to "false" to score inline as a latency rehearsal before switching to active enforcement.
    • Circuit breaker for inference failures. After a run of consecutive inference failures (breakerThreshold, default 5) ext-proc fails open immediately rather than making every request wait out inferenceTimeoutMs, then retries after breakerCooldownMs. Set the threshold to 0 to disable it.
    • Dropped shadow scores are logged, not just counted. Watch kysira_extproc_shadow_dropped_total: sustained drops mean inference is undersized, not that the queue is too small.
    • Request-body cap for scoring. maxBodyBytes (default 1 MiB) bounds what ext-proc accumulates for scoring. Larger bodies are truncated for scoring only and still pass through untouched.
    • New ext-proc metrics for request duration and shadow-queue depth: kysira_extproc_request_duration_seconds, kysira_extproc_shadow_queue_depth.
    • Security and package updates.
    • Decision-log tooling. The log-pull script takes a configurable service name and log view, splits results into malicious vs. false-positive-risk, and can emit a markdown report.

    v0.5.0 — July 27, 2026¶

    • License-signing public key embedded at build time. The proxy image now carries its verification key from the moment it's built and it's wired into the customer Kubernetes chart — no manual key distribution step.
    • Enforcement modes and rollout documented. New docs cover shadow vs. active enforcement and staged rollout.
    • WAF enforcement toggle requires an authenticated admin token.

    v0.4.0 — June 26, 2026¶

    • Decision-log tooling. Added a script and internal runbook for pulling and summarizing ext-proc decision logs, broken down by enforcement impact — useful when tuning thresholds after a shadow-mode run.
    • Cloud Run image access documented. Agent images (proxy, inference, dashboard) and grants for Cloud Run.

    v0.3.0 — June 22, 2026¶

    • Internal tooling and CI reliability improvements.

    v0.2.3 — June 21, 2026¶

    • Security review pass across the proxy, ext-proc, and inference services.

    v0.2.2 / v0.2.1 — June 20–21, 2026¶

    • Licensing service. License issuance and validation updated container.
    • Quickstart rewrite. Docs now cover both the Kubernetes and Cloud Run deployment paths.

    v0.2.0 — June 17, 2026¶

    • New detection coverage: keyless JWT abuse and insecure deserialization (OWASP A07/A08).
    • Dashboard redesign. New "Defense Grid" visualization for the threat monitor, showing the live attack surface as it's scored.

    v0.1.2-alpha — June 12, 2026¶

    • Argus detection engine. Each verdict with the engine that made the call (Argus AI / Model / Signature).
    • Tuned SSTI and SSRF detection coverage.

    v0.1.1-alpha — June 10, 2026¶

    • Added latency and detection metrics.

    v0.1.0-alpha — June 9, 2026¶

    • First alpha release.

    An AI-first platform that scores every HTTP request and kills application-layer attacks in under 100ms before they reach your app, your users, or the news. One container, no code changes.
